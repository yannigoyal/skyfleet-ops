<objective>
Make `./scripts/start_mac.sh` the single command that stands up the whole platform, with the
SQLite database living in the operator's own `database/` directory rather than inside an opaque
Docker-managed volume.

Purpose: DEPLOY-04 and `planning/PLAN.md` §11 both specify a bind mount of the host `database/`
directory so the dispatcher can inspect and back up `skyfleet.db` with ordinary filesystem
tools. The scripts and compose file currently mount a Docker-managed named volume instead, which
satisfies "it persists" but not "the operator can reach it". This plan closes that gap, proves
the built image serves both the API and the static frontend on one port, and closes the
build-context hygiene gap that currently ships the real `.env` to the Docker daemon on every
build.
Output: a rebuilt, verified `skyfleet-ops` image; bind-mounted persistence proven across a
container restart; a documented migration path for the data already sitting in the old named
volume; and a `.dockerignore` that keeps secrets and bulk out of the build context.
</objective>

    volume still holds an older database, that this container now reads and writes
    `database/skyfleet.db` on the host instead, and that `docker/MIGRATION.md` documents how to
    recover the older data. The script must never delete that volume — it prints, it does not
    reclaim. Once the operator removes the volume themselves the notice stops appearing, so it
    self-clears rather than becoming permanent noise. This notice is the mechanism that satisfies
    this plan's prohibition: the storage cutover is announced in the operator's own terminal with
    a recoverable path, instead of presenting later as an inexplicably reset fleet.

    migration step, and because the data in the old volume is exploratory residue from a manual
    run rather than operational history. Then give the preserve path (Option A) as a numbered
    procedure anyone can follow: run `PRAGMA wal_checkpoint(TRUNCATE)` inside the running
    container so `skyfleet.db` alone is authoritative, stop the container so no connection can
    reopen the WAL mid-copy, copy the file out of the named volume into the host `database/`

    named volume afterwards. Explain *why* the checkpoint comes first — SQLite runs in WAL mode

    sidecar and a naive copy of the `.db` file alone would lose them. Note that the host
    `database/` directory in this repository already contains a `skyfleet.db` from local
    non-Docker runs, so the bind-mounted container adopts that file rather than starting empty;
    an operator following Option A should move it aside first.
