<objective>
Close gap G-04-3: the E2E harness fails to start whenever a production container is already
running, because `tests/docker-compose.test.yml`'s `app` service publishes host port 8000 that
nothing in the harness actually needs.

Purpose: UAT test 3 is a blocker. The stated expectation is that the harness runs independently
of whatever else holds host port 8000 — Playwright reaches the app over the internal Compose
network and the healthcheck runs inside the app container, so the host publish buys the harness
nothing while costing it the ability to coexist with the documented single-command launch.
Output: a harness that binds no host port, plus operator documentation that states the real
cause and no longer prescribes a manual pre-stop workaround.
</objective>

`.planning/debug/e2e-harness-port-conflict.md` — do not re-investigate. Established facts:

  README note telling the operator to stop the other container first is a workaround, not the
  isolation the scenario calls for. The adequate fix is structural.

The gap's two `missing` items are: drop (or remap) the `ports:` mapping on the app service, and
correct the README's causal explanation to name `scripts/start_mac.sh`.
