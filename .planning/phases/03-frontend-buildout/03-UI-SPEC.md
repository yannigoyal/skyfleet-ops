## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — plain HTML elements + Tailwind utility classes (established pattern in `Header.tsx`, `FleetRosterPanel.tsx`, `ConnectionDot.tsx`) |

**shadcn gate note:** `components.json` was not found and the stack is Next.js, which normally triggers the shadcn init prompt. This is a non-interactive research pass, so the default was resolved as **do not initialize shadcn**: the project already has three production components built entirely from plain HTML + Tailwind with zero component-library dependency, `.claude/CLAUDE.md`'s global preference is "avoid unnecessary dependencies," and `03-CONTEXT.md`'s decisions (D-01…D-16) already describe every new component (detail panel, heatmap, budget chart, missions table, dispatch bar, chat panel) in terms of plain elements, not shadcn primitives. If the user wants shadcn after all, re-run this gate manually before planning starts — it is a cheap, reversible decision at this stage.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (e.g. table cell `py-2`) |
| md | 16px | Default element spacing (panel `p-4`, page grid `gap-4`) |
| lg | 24px | Section padding (page `p-6`, layout `gap-6`) |
| xl | 32px | Layout gaps between major regions |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: **12px** (`py-3` / `gap-3`) — already used in the existing `Header.tsx` for the header row's vertical padding and brand-cluster gap. Carry this exception forward for any new header-row-adjacent spacing (e.g. the chat panel's own header bar) rather than introducing a third off-scale value.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label | 12px (`text-xs`) | 400 (regular) | 1.4 |
| Heading | 14px (`text-sm`) | 600 (semibold) | 1.2 |
| Display | 18px (`text-lg`) | 600 (semibold) | 1.2 |

Two weights declared: 400 (regular) and 600 (semibold) — use these for all new Phase 3 components (detail panel, heatmap, budget chart, missions table, dispatch bar, chat panel).

**Pre-existing exception (do not change, out of this phase's scope):** the "SkyFleet Ops" brand wordmark in `Header.tsx` uses `font-bold` (700, `text-lg`). This predates Phase 3 and FE-07 only *extends* the header with live data — it does not restyle the wordmark. Treat 700 as a single, locked, non-repeating exception; do not use it anywhere else.

Panel/section titles (e.g. "Fleet Roster", "Missions", "Flight Director") use the **Heading** role (14px/600), matching the existing `FleetRosterPanel.tsx` title bar (`text-sm font-semibold text-slate-300`).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0e14` (`ops.bg`) | Page background |
| Secondary (30%) | `#12161f` (`ops.panel`) / `#232a38` (`ops.border`) | Panel/card surfaces, sidebar, table headers, dividers |
| Accent (10%) | `#17a2b8` (`ops.teal`) | See breakdown below — accent is a compound three-color system per `planning/PLAN.md` §2, not a single hue |
| Destructive | `#ef4444` (Tailwind `red-500`/`red-400`) | Critical battery, disconnected status, failed actions, error text |

Accent reserved for (exact elements only — PLAN.md's tri-color scheme, already partially in production code):

- **`ops.teal` `#17a2b8`** — numeric/data emphasis: `font-mono` readouts (energy budget value, active mission count, telemetry figures in the detail panel), the charging-battery flash animation. This is the accent used most broadly across panels.
- **`ops.amber` `#f2a900`** — the brand wordmark (pre-existing), the "connecting" SSE status dot, the draining-battery flash animation, and the battery-health warning band (20–50%).
- **`ops.signal` `#e8622c`** — reserved **exclusively** for the Launch button / dispatch primary CTA (PLAN.md: "Signal Orange — launch/dispatch actions"). Do not reuse this color for any other interactive element.

Additional semantic color already established in the codebase (not one of the `ops.*` tokens, but load-bearing — declared here so the executor doesn't invent a new "success" hue):

- **Success/healthy** — Tailwind `emerald-400` (text) / `emerald-500` (bg/dot): battery ≥50% color, the "connected" SSE dot, heatmap healthy-battery cells, and the green "Dispatched" confirmation badge (D-06). This is the actual code convention in `FleetRosterPanel.tsx`'s `batteryColor()` and `ConnectionDot.tsx` — note that `03-CONTEXT.md`'s D-11 prose says the heatmap "reuses the `ops.amber`/`ops.teal`/`ops.signal` tokens," but the real precedent it points to (`batteryColor()`) actually uses `emerald-400` for the healthy band, not `ops.teal`. Follow the code precedent (`emerald`), not the prose, to stay consistent with the existing roster panel.
- **Destructive/critical** — `red-400` (text) / `red-500` (bg/dot): battery <20% color, "disconnected" SSE dot, heatmap critical-battery cells, red "Failed: {reason}" confirmation badge (D-06), dispatch-bar inline error text (D-14).

Battery-health 3-band mapping (D-11, using the corrected color precedent above): green (`emerald-400`) ≥50%, amber (`ops.amber`) 20–50%, red (`red-400`) <20%.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Launch Mission" (dispatch bar launch button, `ops.signal` background) |
| Secondary action | "Recall" (dispatch bar recall button, on the selected/active drone) |
| Empty state — Missions table | Heading: "No active missions" · Body: "Launch a mission from the dispatch bar to see it here." |
| Empty state — Detail panel (no active mission, D-16) | "No active mission" — plain inline message; battery/altitude/speed telemetry charts still render normally beneath it |
| Empty state — Chat transcript (first load) | Heading: "Flight Director standing by" · Body: "Ask about fleet status or dispatch a mission — e.g. \"Launch FALCON-03 to Riverside\"." |
| Empty state — Fleet heatmap | Not user-facing copy — D-10 keeps all drones visible at a fixed minimum weight (0.1 kWh) so the heatmap never renders visually empty, even at 0 active missions |
| Error state — Dispatch bar | "{backend reason-coded message, verbatim}" rendered inline below the form in `red-400` — no client-side re-validation or rewording (D-14) |
| Error state — Chat transport failure | "Connection error — try sending your message again." as a plain red inline system message in the transcript (distinct from a failed-action confirmation card, since no action was ever executed) |
| Error state — Chat action failure (D-06) | Confirmation card outcome badge: "Failed: {reason}" in `red-400`/`red-500` |
| Success state — Chat action (D-06) | Confirmation card format: "{ACTION VERB} {DRONE_ID} → {ZONE} ({DISTANCE}km)" with a green "Dispatched" (or "Recalled" / "Added" / "Removed") badge in `emerald-400`/`emerald-500` |
| Destructive confirmation | None — Recall and AI-issued actions execute instantly with no confirmation dialog. This is an explicit, already-ratified product decision (`planning/PLAN.md` Out of Scope; `REQUIREMENTS.md` Out of Scope table), mitigated by immediate inline result feedback (dispatch-bar error text, chat confirmation badges) rather than a confirm step. |
| Status labels — Missions table | `en_route` → "En Route" · `delivered` → "Delivered" · `recalled` → "Recalled" (extends the existing `STATUS_LABEL` pattern from `FleetRosterPanel.tsx`) |
| Detail panel drone-dropped-from-snapshot state | "Drone offline or removed from roster" in place of stale telemetry |

| error | SSE disconnect (telemetry stream, nav-adjacent status indicator) | ✅ covered | Existing `ConnectionDot` "Disconnected" state + native `EventSource` auto-reconnect (`planning/PLAN.md` §6) — pre-existing pattern, no new copy needed |

| overflow | Missions table — many concurrent/historical missions (list-collection) | ✅ covered | Same internal-scroll pattern as the roster table; `thead` stays visually anchored |
| overflow | Chat transcript (list-collection) | ✅ covered | FE-08's explicit "scrolling conversation history" requirement; auto-scrolls to the newest message on each new turn |
| overflow | Zone name / confirmation-card params — free-text field (D-15) (static-content) | 🧪 backstop | Truncate at a fixed max width with ellipsis + native `title` attribute for the full value; verify via a held-out long-string render test |

| zero-one-many | Fleet heatmap — 0/1/many active missions (list-collection) | ✅ covered | Zero handled by D-10; Recharts `Treemap` layout scales naturally for one/many — no singular/plural copy needed (purely visual element) |
| partial | Detail panel — selected drone drops out of the live SSE snapshot (removed from roster, or momentarily absent on one tick) (form/static-content) | 🧪 backstop | Shows "Drone offline or removed from roster" (see Copywriting Contract) instead of freezing on stale/blank last-known values; verify via a held-out test that removes a drone mid-selection |
