<objective>
Give the operator fleet-wide situational awareness at a glance: a treemap where every drone
is a rectangle sized by how much energy its mission is spending and coloured by how healthy
its battery is, beside a line chart of the remaining energy budget over time.

Purpose: the roster table answers "what is drone FALCON-07 doing"; these two visualisations
answer "where is my energy going" and "am I about to run out" — the questions that actually
drive a dispatcher's next decision. Clicking any heatmap cell drops straight into the plan
04 detail panel, so the overview and the detail share one selection.
Output: both visualisations mounted in the console grid, with the full fleet visible even at
zero active missions.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend snapshot/mission payloads → SVG chart coordinates | Server-supplied numerics become geometry; a non-finite value produces invalid SVG |
| Drone identifiers → SVG text nodes | Identifier strings are rendered inside the chart's SVG tree |
| Colour encoding → operator's criticality judgement | Battery criticality is communicated visually to a human making dispatch decisions |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-18 | Tampering | Non-finite `energy_cost_kwh` or `remaining_kwh` reaching chart geometry | medium | mitigate | Floor every heatmap weight at `IDLE_HEATMAP_WEIGHT_KWH` and format every displayed numeric through `.toFixed(n)` before it reaches a text node, so a `NaN`/`Infinity` cannot render as raw text or collapse the layout. The backend already guards the write path at the Pydantic and `isfinite` layers (Phase 2 code review). |
| T-03-19 | Tampering | Drone id rendered inside the Treemap's SVG subtree | medium | mitigate | Render ids as SVG `text` children through JSX interpolation, which React escapes; the cell renderer contains only `g`/`rect`/`text` primitives and behavior test 5 asserts the `svg` subtree holds zero `div` and zero `foreignObject` nodes, so no HTML injection surface exists inside the chart. |
| T-03-20 | Repudiation | Colour-only criticality signalling | medium | mitigate | Recorded as an explicit judgment-tier prohibition in this plan's must_haves and satisfied in implementation by rendering the battery percentage as SVG text in every legible cell, so a colour-blind dispatcher is not silently denied the critical signal. |
| T-03-21 | Denial of Service | Second polling loop from `EnergyBudgetChart` alongside the provider's | low | accept | One additional 5-second GET against a local SQLite-backed endpoint in a single-operator demo. The unmount guard prevents leaked closures accumulating, which is the failure mode that would actually matter over a long session. |
| T-03-22 | Information Disclosure | Budget history exposed without authentication | low | accept | `GET /api/fleet/history` is an existing unauthenticated endpoint; authentication is out of scope project-wide and ASVS V4 is recorded as not applicable in `03-RESEARCH.md` § Security Domain. This phase adds a consumer, not a new exposure. |
</threat_model>
