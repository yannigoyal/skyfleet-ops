<objective>
Stand up the frontend validation harness that every other Phase 3 plan's automated
verification depends on, behind a blocking package-legitimacy gate.

This plan owns **no user-facing requirement of its own**. It is listed against all nine
FE requirements because it is what makes their `<automated>` verify commands runnable at
all — each FE-0x requirement is separately owned and delivered by plans 02-06. Today
`frontend/package.json` declares `"test": "vitest run"` with **no** `vitest.config.ts`,
so Vitest would run in its default `node` environment and every React DOM component test
would fail on a missing `document`. Three packages the harness needs (`jsdom`,
`@testing-library/jest-dom`, `@vitejs/plugin-react`) are physically present in
`node_modules` but **extraneous** — absent from `package-lock.json` — so a clean
`npm ci` is not guaranteed to reproduce them.

Purpose: without this, every subsequent plan's `<automated>` gate is unrunnable and
Phase 3 would ship on manual inspection alone.
Output: `vitest.config.ts`, `vitest.setup.ts`, three declared devDependencies, and one
smoke test proving the harness works against an existing component.
</objective>
